# 기준정보 CSV

부트캠프 자료(`data/raw/`)에서 옮겨 온 기준정보입니다. 이후에는 이 CSV를 기준으로 관리하며, seed SQL은 이 파일들로 만듭니다.
인코딩은 UTF-8(BOM 없음)입니다.

| 파일 | 내용 | 건수 | 출처 |
| --- | --- | --- | --- |
| `items.csv` | 품목 (완제품, 반제품, 원자재) | 10 | 3주차 과제 Item Master |
| `bom.csv` | BOM (상위 → 하위, 소요량, 투입 공정) | 10 | 3주차 과제 BOM 표 |
| `processes.csv` | 공정 | 7 | 1차 자료 공정정보 |
| `work_centers.csv` | 작업장 | 7 | 3주차 과제 Work Center |
| `routings.csv` | 라우팅 (공정 순서, 표준시간, 셋업 시간, Batch 크기) | 7 | 3주차 과제 Routing, 3차 자료 |
| `equipment.csv` | 설비 | 12 | 2차 자료 설비 기본정보 (CNC 5대), 3차 자료 (그 외 7대) |
| `inspection_specs.csv` | 공정별 검사 항목과 규격 (LSL/USL) | 14 | 3차 자료 공정별 품질 기준 |
| `common_codes.csv` | 공통코드 (품목유형, 작업지시 상태, 설비 상태, 비가동 사유, 불량 유형) | 38 | 2차 자료 비가동 내역, 1차 자료 |

## 원본에서 바꾼 점

- **품목유형**: 3주차 과제의 SAP 용어(FERT, HALB, RM)를 품번 접두어와 같은 `FG`, `SF`, `RM`으로 바꿨습니다.
- **BOM Level**: 원본 표의 Level 번호가 실제 트리 깊이와 달라 저장하지 않습니다. Level은 재귀 쿼리로 계산합니다.
- **라우팅 표준시간**: Batch 공정(열처리, 세척)은 개당 환산값(2.4분, 0.4분) 대신 Batch당 시간(480분, 20분)과 `time_basis = BATCH`로 저장합니다.
- **세척·검사 산출물**: 별도 품번이 없어 `SF-SFT-040`(연삭 샤프트)을 그대로 씁니다. 상태 변화는 LOT 이력으로 구분합니다.
- **검사 규격**: "Ø38 ±0.05mm" 같은 표기를 기준값(nominal), 하한(LSL), 상한(USL)으로 나눴습니다. "Ra 3.2 이하"처럼 상한만 있는 항목은 LSL을 비워 둡니다.
- **비가동 사유**: 원본의 한글 대분류 5종, 소분류 19종에 영문 코드를 붙였습니다. 원본 220건의 사유가 모두 코드표에 있는지 확인했습니다.
- **거래처**: 원본에 있는 실제 거래처명은 CSV에 넣지 않았습니다. 필요하면 가명(예: A사)을 씁니다.
