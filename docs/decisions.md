# 기술 결정 기록

## 2026-10-07

| 항목 | 결정 | 이유 | 검토한 대안 |
| --- | --- | --- | --- |
| DB | MSSQL (Docker 컨테이너) | 국내 MES 현장에서 가장 많이 쓰이고, 프로시저와 재귀 CTE(LOT 추적)를 다뤄볼 수 있음 | MySQL |
| 설비 통신 | MQTT (Mosquitto 브로커) | 설비 연동에 널리 쓰이는 경량 발행/구독 프로토콜. 설비가 늘어도 서버 코드를 바꾸지 않아도 됨 | TCP 소켓, REST 주기 전송 |
| 관리자 웹 | Thymeleaf (Spring 서버 렌더링) | 백엔드와 MES 직무에 집중하기 위해 프론트엔드 빌드를 따로 두지 않음 | React |
| 저장소 | `Desktop/MES` 독립 Git 저장소 | 홈 폴더 전체가 상위 Git 저장소로 잡혀 있어 개인 파일 노출 위험이 있었음 | - |
| 원본 자료 | `data/raw/`에 보관, `.gitignore`로 제외 | 거래처 실명이 포함되어 있음. 공개용은 가명 처리한 CSV만 사용 | - |
| Java | 21 (LTS) | 개발 PC에 설치된 LTS 버전. 계획서의 17보다 최신이며 Spring Boot 4와 호환 | 17 |
| Spring Boot | 4.0.8 | MyBatis 스타터가 4.0.x까지만 지원해 4.1 대신 4.0 라인을 선택 | 4.1.1 |
| .NET 대상 | net8.0 (LTS), SDK 9로 빌드 | 계획서 기준. 설치된 .NET 8 런타임으로 실행 가능 | net9.0 |
| 서버 테스트 DB | H2 (MSSQL 호환 모드) | MSSQL 컨테이너 없이도 `./gradlew build`가 통과하도록 함 | Testcontainers |

## 2026-10-17 POP

| 항목 | 결정 | 이유 | 검토한 대안 |
| --- | --- | --- | --- |
| POP 로그인 | 사번만 입력 (비밀번호 없음), 요청마다 workerId 전송 | 현장 단말은 여러 작업자가 돌려 쓰고 사원증 바코드로 찍는 경우가 많음. 인증은 이후 단계에서 추가 | 세션·JWT 로그인 |
| 실적 중복 방지 | POP가 요청마다 GUID(request_id)를 붙이고 서버가 필터 UNIQUE 인덱스로 한 번만 저장 | 응답을 못 받은 POP가 다시 보내도 실적이 두 번 생기지 않음 (설비 message_id와 같은 방식) | 수량 비교로 중복 추정 |
| 실적 수정 | 수정 없이 취소 표시 후 재등록 | 누가 언제 바꿨는지 남음 (감사 추적) | UPDATE |
| 화면 로직 테스트 | ViewModel이 IMesApi, IDialogService에만 의존 | 서버·창 없이 xUnit으로 재전송·입력 잠금 규칙을 시험 | UI 자동화 테스트만 |
